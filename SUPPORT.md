# Support

Media Cookie Broker is an early public preview maintained on a best-effort basis.

## Before asking for help

Start with:

- the quick start in [README.md](README.md);
- [installation and operations](docs/INSTALLATION.md);
- [cookie-sync integration](docs/COOKIE_SYNC.md);
- [known limitations](docs/KNOWN_LIMITATIONS.md);
- the project's printed `status`, `logs`, and `doctor` commands.

Search existing issues before opening a new one. Use the structured configuration-help form and include the smallest safe reproduction.

## Never publish credentials

Do not post real cookies, exported cookie files, passwords, master keys, Authorization headers, account identifiers, private endpoints, or unredacted production logs.

Replace private data with unmistakably fake values such as `not-a-real-cookie` and `example.invalid`. Treat synchronized cookie files and metadata sidecars as private even when investigating an ordinary configuration problem.

## Security reports

Do not use public support issues for vulnerabilities or suspected credential exposure. Follow [SECURITY.md](SECURITY.md) and use GitHub private vulnerability reporting.

## Scope

Public issues are appropriate for reproducible project defects, documentation errors, installation questions, and concrete integration proposals.

The project cannot provide private deployment administration, account recovery, upstream login automation, CAPTCHA or 2FA bypass, or guarantees about provider anti-bot behavior.
